# paperless-gpt

Titles, tags, correspondents and OCR for an existing
[Paperless-ngx](../paperless-ngx/), generated by a language model you point it
at. One container: it keeps a small database of what it changed and renders the
prompts it uses, and everything else lives in Paperless-ngx.
Upstream: [icereed/paperless-gpt](https://github.com/icereed/paperless-gpt).

## Architecture

```text
Operator → Traefik (TLS, access policy, basic auth) → app :8080
                                                        │
                        ┌───────────────────────────────┼───────────────┐
              Paperless-ngx API                 model server        volumes/
              (token, over proxy-public)   (Ollama, LiteLLM, hosted)  db · config · prompts
```

It reaches Paperless-ngx and the model by their container aliases on
`proxy-public`, so neither call leaves the host for a local model.

## It has no authentication — read this first

Upstream states it plainly: the interface and every `/api/*` endpoint answer
whoever reaches the port. Measured here against v0.28.0 — `/api/tags`,
`/api/documents`, `/api/prompts` and `/api/settings` all returned 200 with no
credentials.

Whoever reaches it can rewrite documents in the connected Paperless-ngx, start
model and OCR jobs against the configured keys, and change its settings. This
stack therefore ships **two** gates, and neither is optional:

1. `APP_TRAEFIK_ACCESS=acc-tailscale` — the router answers the VPN only.
2. A basic-auth middleware in front of the router, with the hash in the
   gitignored `.env`.

`.env.example` has the command that generates the hash. **Every `$` in it has to
be doubled**, or Compose expands `$apr1` and `$2y` as variable names and Traefik
receives a few leftover characters — measured, not guessed.

The API token you give it decides what it may do to your documents: create it in
Paperless-ngx for a user with exactly those permissions, not for a superuser.

## Try it locally

Runs on `http://localhost:8080` without Traefik, DNS or a certificate — and
therefore without the password gate. It needs a reachable Paperless-ngx and a
model server to do any work.

```bash
cp .env.local.example .env.local          # point it at your Paperless-ngx and model
mkdir -p .secrets volumes/db volumes/config volumes/prompts
printf '%s' 'your-paperless-api-token' > .secrets/paperless_api_token.txt
touch .secrets/llm_api_key.txt
docker compose -f docker-compose.local.yml --env-file .env.local up -d
# http://localhost:8080
docker compose -f docker-compose.local.yml --env-file .env.local down
```

## Setup

```bash
cp .env.example .env                      # host name, Paperless URL, model, basic auth
mkdir -p .secrets volumes/db volumes/config volumes/prompts
printf '%s' 'the-paperless-api-token' > .secrets/paperless_api_token.txt
touch .secrets/llm_api_key.txt            # a key only for a hosted model
sudo chown -R 1000:1000 volumes/db volumes/config volumes/prompts
docker compose up -d
docker compose logs paperless-gpt-app --follow   # watch for: Server started on interface :8080
```

On the first start it creates its three tags in Paperless-ngx —
`paperless-gpt`, `paperless-gpt-auto` and `paperless-gpt-failed` by default. Tag
a document with the first one and it appears in the interface for review; the
second one processes without asking. The third marks what failed, so a document
does not loop.

If Paperless-ngx is unreachable, the interface still starts and the log carries
the failure every twenty seconds — that is what a wrong URL or a wrong token
looks like.

## Where the model runs

| `LLM_PROVIDER` | Points at | Needs a key |
|---|---|---|
| `ollama` | [`apps/ollama`](../ollama/) over `proxy-public` | no |
| `openai` | any OpenAI-compatible endpoint, [`apps/litellm`](../litellm/) included, through `OPENAI_BASE_URL` | yes, in `.secrets/llm_api_key.txt` |

OCR for documents Paperless-ngx could not read is a second choice:
`OCR_PROVIDER=llm` sends page images to a vision model, `docling` sends them to
a Docling server — [`apps/docling-serve`](../docling-serve/) is one. Google
Document AI and Azure Document Intelligence are supported upstream and both send
the pages to that vendor.

## Known limits

- **Its own API is unauthenticated**, which is why the two gates above are not
  optional.
- **The rate limit is not measured.** The chain ships `sec-2` and the interface
  is a React application; no first-load count has been taken behind Traefik.
- **The basic-auth hash sits in `.env`**, not in a Docker Secret: a Traefik
  middleware reads its users from the label. `docs/standards/secrets.md` calls
  that Pattern 3, a documented deviation.
- **Nothing here has run behind Traefik yet.** The stack is `scaffolded`: the
  hardening, the token path and the interface were verified on the image, the
  route and a real document were not.

## Backup

| | |
|---|---|
| **Database** | SQLite · `./volumes/db/modification_history.db` — what it changed, and the suggestion jobs |
| **State** | `./volumes/config/settings.json` — the settings changed in the interface · `./volumes/prompts` — prompt templates, once edited |
| **Reproducible** | Everything else. The documents themselves live in Paperless-ngx and are backed up there |
| **Quiescing** | Stop the container, or use `sqlite3 .backup` — the database is written live |

```yaml
# /etc/borgmatic/config.yaml
source_directories:
  - /srv/secure-docker-blueprint/apps/paperless-gpt/volumes

sqlite_databases:
  - name: paperless_gpt
    path: /srv/secure-docker-blueprint/apps/paperless-gpt/volumes/db/modification_history.db
```

Restore: put the three directories back, keep them owned by uid 1000, start the
container. Nothing here is irreplaceable — losing it costs the record of what
was changed and the customised prompts, not the documents.
