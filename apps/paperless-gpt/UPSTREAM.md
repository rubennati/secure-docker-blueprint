## What we use

- `ghcr.io/icereed/paperless-gpt:v0.28.0`, one container. A Go binary with its
  interface built in.
- Its own state is small: a SQLite database of what it changed, a settings file,
  and the prompt templates once they are edited.
- Paperless-ngx and the model server are separate stacks; this one calls them
  over `proxy-public` and keeps no datastore of its own.

## What we changed and why

| Change | Reason |
|--------|--------|
| A basic-auth middleware on the router, plus `acc-tailscale` | The application has no authentication. Measured against v0.28.0: `/api/tags`, `/api/documents`, `/api/prompts` and `/api/settings` each answered 200 without credentials |
| `APP_BASIC_AUTH_USERS` in `.env`, with every `$` doubled | Traefik's basic-auth middleware reads its users from the label, so the value cannot be a Docker Secret — `secrets.md` Pattern 3. The doubling is not cosmetic: measured, `ops:$apr1$…` from `.env` reaches the container label as `ops:/ZWf571`, because Compose expands `$apr1` and the rest as variable names. With `$$` the label carries the real hash |
| `config/entrypoint.sh` exports `PAPERLESS_API_TOKEN` and the model key | No `_FILE` variant exists for either. Verified against a stub API: the token from the Docker Secret is sent as `Authorization: Token …` |
| `user: "${APP_UID}:${APP_GID}"` | Started as root the image's entrypoint creates a user from `PUID`/`PGID`, `chown -R`s `/app` and drops privileges — which fails against a read-only filesystem. Its non-root branch skips all of that and execs the binary directly |
| Three bind mounts under `/app` (`db`, `config`, `prompts`) | The entrypoint creates those directories; with `read_only: true` they have to exist as mounts |
| `read_only: true`, `cap_drop: ALL`, `tmpfs: /tmp` | Verified; only `/tmp` and the three mounts are written |
| Healthcheck on `/` with `wget` | There is no health endpoint, and the image carries `wget` rather than `curl` |
| `OCR_PROVIDER` and `DOCLING_URL` exposed in `.env.example` | `apps/docling-serve` already exists here and is one of the OCR backends upstream supports |

## Verified on the image (2026-09-23)

Not a host verification: this ran the stack's own `docker-compose.local.yml`,
without Traefik and without TLS, against a stub that answered the Paperless API.

- Healthy with `read_only`, `cap_drop: ALL`, `no-new-privileges` as uid 1000;
  `Server started on interface :8080`, and `/` answered 200.
- The API token from the Docker Secret reached Paperless as
  `Authorization: Token …` on `/api/tags/`, `/api/custom_fields/` and the tag
  lookups for its three tags.
- With Paperless unreachable the interface still starts, and the failure is
  logged every twenty seconds.
- Its own API answered 200 without credentials on four endpoints — the reason
  for the two gates above.
- `volumes/db/modification_history.db` and `volumes/config/settings.json` were
  written; idle memory 9 MiB.
- Compose interpolation of the basic-auth hash was checked against the real
  container label, in both the escaped and the unescaped form.

What a host run still has to establish: the route behind Traefik with TLS, the
basic-auth prompt and a refused client, a real document through a model, an OCR
run, and the restore in the README.

## Upgrade checklist

1. Read the release notes — https://github.com/icereed/paperless-gpt/releases
2. Raise `APP_TAG` in `.env` and in `.env.local.example`
3. `docker compose pull && docker compose up -d`
4. `docker compose logs paperless-gpt-app` — `Server started on interface :8080`,
   then no repeated Paperless errors
5. Tag one document with `MANUAL_TAG` and confirm a suggestion appears
6. Record the result in `Last verified` once it ran behind Traefik
