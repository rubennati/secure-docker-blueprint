PhotoPrism indexes a photo library, classifies what is in the pictures, and
recognises faces and places. Two containers — the Go server with its models, and
MariaDB.

<StackEvidence stack="apps/photoprism"
  gap="everything below. The stack has never been brought up here: the first index run, the model download and the memory behaviour under large RAW or video files are read from the stack's files rather than observed." />

Needs: [Traefik](/infrastructure/traefik/) running, a domain, and disk space —
the first start downloads roughly 1 GB of classification models.

## Installation

From `apps/photoprism/`:

<Steps>

1. Copy the environment file:

   ```bash
   cp .env.example .env
   ```

   Set `APP_TRAEFIK_HOST`, `TZ`, `PUID`/`PGID`, `SITE_TITLE`, and
   `ORIGINALS_PATH` — the last one is where your photos live and it may point
   outside the stack directory.

2. Generate the database secrets and mirror the password into `.env`.
   PhotoPrism has no `_FILE` form for its database password, so the value exists
   twice:

   ```bash
   mkdir -p .secrets
   openssl rand -base64 32 | tr -d '\n' > .secrets/db_pwd.txt
   openssl rand -base64 32 | tr -d '\n' > .secrets/db_root_pwd.txt
   sed -i "s|^DB_PWD_INLINE=.*|DB_PWD_INLINE=$(cat .secrets/db_pwd.txt)|" .env
   ```

3. Set the initial administrator password, which is read once at first start:

   ```bash
   ADMIN_PWD_VAL=$(openssl rand -base64 24 | tr -d '\n')
   sed -i "s|^ADMIN_PASSWORD=.*|ADMIN_PASSWORD=${ADMIN_PWD_VAL}|" .env
   echo "Initial admin password: ${ADMIN_PWD_VAL}"
   ```

   Keep that value somewhere safe. After the first login, change the password in
   the interface and remove it from `.env`.

4. Create the volumes:

   ```bash
   mkdir -p volumes/database volumes/storage volumes/originals
   ```

5. Start it. The first run downloads the classification models and takes several
   minutes:

   ```bash
   docker compose up -d
   docker compose logs app --follow
   ```

   Wait for `server: listening on 0.0.0.0:2342`.

6. Open `https://<APP_TRAEFIK_HOST>` and log in with `ADMIN_USER` and the
   password from step 3.

</Steps>

## Verify

```bash
docker compose ps                                    # two services, healthy
curl -fsSI https://<APP_TRAEFIK_HOST>/api/v1/status  # 200
```

Then put a few photos into the originals path and start an index run from the
interface. Pictures appearing with thumbnails and detected content is the check —
the server answers long before indexing works.

## Going further

### Memory during indexing

The indexer can reach several gigabytes while processing large RAW files or
video. The stack sets no memory limit for that reason: a ceiling the indexer
touches ends as an out-of-memory kill mid-run. Provide at least 4 GB of swap
instead.

### Date-based versions

PhotoPrism tags releases by date — `260601` is 1 June 2026. There is no semantic
version to read, so the release notes are the only way to know what a bump
contains.

### If MariaDB crashes on an older kernel

Upstream works around an `io_uring` issue by running MariaDB with seccomp and
AppArmor unconfined. This stack keeps the defaults; the block is present in
`docker-compose.yml` and commented out, to be enabled only if that crash appears.

## Backup

| | |
|---|---|
| **Database** | MariaDB, container `photoprism-db`, database `photoprism`, user `photoprism` |
| **Password** | `.secrets/db_pwd.txt` |
| **The library** | `ORIGINALS_PATH` — the photos, which may sit outside the stack directory |
| **Also needed** | `volumes/storage/sidecar` — edits and metadata written back |
| **Rebuildable** | the rest of `volumes/storage` — thumbnail cache, regenerated by an index run |
| **Quiescing** | Not needed for the dump. |

For [borgmatic](/operations/backup/):

```yaml
mariadb_databases:
    - name: photoprism
      container: photoprism-db
      username: photoprism
      password: "{credential file /srv/docker/apps/photoprism/.secrets/db_pwd.txt}"
```

Exclude the thumbnail cache subdirectory rather than all of `volumes/storage`.
Most of that tree is cache, but the sidecar files in it carry edits and metadata
that exist nowhere else.

Restore order: database, then originals and sidecars, then the application.

## Updates

<Steps>

1. Read the [release notes](https://github.com/photoprism/photoprism/releases) —
   the tag is a date, so it is the only description of what changed.

2. Back up the database, the originals and the sidecar directory together.

3. Raise `APP_TAG` in `.env`, then:

   ```bash
   docker compose pull && docker compose up -d
   docker compose logs app --follow
   ```

4. Open the library and run an index. A schema change surfaces during indexing
   rather than at start.

</Steps>

## Troubleshooting

**The indexer stops partway through a large file.** Out of memory. Add swap
rather than a memory limit.

**Login fails with the password from `.env`.** `ADMIN_PASSWORD` is read only at
first start. If the stack has run before, the password is whatever is stored in
the database.

**MariaDB crashes on start.** The `io_uring` case. Uncomment the seccomp and
AppArmor block in `docker-compose.yml`.

**Photos are visible but nothing is classified.** The model download did not
finish. Check `docker compose logs app` from the first start.
