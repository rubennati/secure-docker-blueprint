Listmonk manages subscribers, sends campaigns, handles double opt-in and tracks
opens and clicks. Two containers — a single Go binary and PostgreSQL.

<StackEvidence stack="business/listmonk"
  gap="everything below. The stack has never been brought up here: the install path, the admin wizard, sending through a real relay and bounce handling are all read from the stack's files rather than observed." />

Needs: [Traefik](/infrastructure/traefik/) running, a domain, and an SMTP relay
you enter after installation.

## Installation

From `business/listmonk/`:

<Steps>

1. Copy the environment file and set `APP_TRAEFIK_HOST` and `TZ`:

   ```bash
   cp .env.example .env
   ```

2. Generate the database password and write it into `.env` as well. Listmonk has
   no `_FILE` form for its database password, so the value exists twice — once as
   the secret file, once inline:

   ```bash
   mkdir -p .secrets volumes/postgres volumes/uploads
   openssl rand -base64 32 | tr -d '\n' > .secrets/db_pwd.txt
   sed -i "s|^DB_PWD_INLINE=.*|DB_PWD_INLINE=$(cat .secrets/db_pwd.txt)|" .env
   ```

3. Start it. First boot creates the schema:

   ```bash
   docker compose up -d
   docker compose logs app --follow
   ```

   Wait for `http server started on [::]:9000`.

4. Open `https://<APP_TRAEFIK_HOST>`. The first visit shows a wizard that creates
   the super admin account — there are no administrator credentials in `.env` to
   set.

5. In the interface, go to **Settings → SMTP** and enter the relay credentials.
   They are stored encrypted in the database rather than in a file.

</Steps>

## Verify

```bash
docker compose ps   # two services, healthy
```

Then send a campaign to a list containing only your own address, and confirm it
arrives. Sending is the whole purpose of the stack and the part a running
container says nothing about.

## Going further

### Admin behind the VPN, subscribers on the internet

The stack ships `acc-public` with `sec-2e`, because subscriber endpoints —
`/subscription/*`, `/link/*`, `/campaign/*` — have to work for people who are not
on your VPN. That leaves `/admin` public too.

Splitting the two means a second Traefik router with a higher priority, scoped to
`/admin` and carrying `acc-tailscale@file` with `sec-3@file`; the existing router
keeps the subscriber paths. The label block is in
[`business/listmonk/README.md`](https://github.com/rubennati/secure-docker-blueprint/blob/main/business/listmonk/README.md).

### Why `sec-2e` rather than `sec-2`

The campaign and template preview renders inside an iframe from the same origin.
`sec-2` sends `X-Frame-Options: deny`, which blocks it; `sec-2e` sends
`SAMEORIGIN` instead.

### Bounce handling

Bounces need either IMAP access to the sending mailbox or a relay that posts
bounce webhooks. Without one of the two, addresses that no longer exist stay on
the list and quietly damage the sending reputation.

### The version check

Listmonk asks `update.listmonk.app` whether a newer version exists — a plain GET
with no payload and no installation identifier, so the vendor sees the source
address and the timing. It is on by default and switched off under
**Settings → General → Check for updates**.

## Backup

| | |
|---|---|
| **Database** | PostgreSQL, container `listmonk-db`, database `listmonk`, user `listmonk` |
| **Password** | `.secrets/db_pwd.txt` |
| **State** | `volumes/postgres` · `volumes/uploads` (media used in campaigns) |
| **Quiescing** | Not needed — the dump is consistent on its own. |

For [borgmatic](/operations/backup/):

```yaml
postgresql_databases:
    - name: listmonk
      container: listmonk-db
      username: listmonk
      password: "{credential file /srv/docker/business/listmonk/.secrets/db_pwd.txt}"
```

:::caution
Restoring an older database here is not a neutral act. Subscriptions and their
opt-in state are rows, so an older snapshot can bring back addresses that
unsubscribed after it was taken — and the next campaign mails them again. Compare
the subscriber table against the unsubscribe log before the first send following
a restore.
:::

Restore order: database, then the application.

## Updates

<Steps>

1. Read the [release notes](https://github.com/knadh/listmonk/releases).

2. Back up the database and `volumes/uploads` together.

3. Raise `APP_TAG` in `.env`, then:

   ```bash
   docker compose pull && docker compose up -d
   docker compose logs app --follow
   ```

4. Open a campaign and a template. Schema changes surface in the editor rather
   than at start.

</Steps>

## Troubleshooting

**The interface asks for administrator credentials that are not in `.env`.**
Listmonk v6 removed them from configuration. The wizard on first visit is where
the account is created; the older `ADMIN_USER` and `ADMIN_PASSWORD` variables are
ignored.

**A banner asks you to remove `admin_username` from the configuration.** Those
fields are already absent here. The banner can be dismissed.

**The campaign preview is blank.** The iframe is being blocked. Confirm
`APP_TRAEFIK_SECURITY=sec-2e` rather than `sec-2`.
