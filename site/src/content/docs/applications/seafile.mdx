Seafile syncs files between devices and shares them with other people, with
desktop and mobile clients and optional collaborative editing. Eight containers,
split across five compose files so the optional parts can be switched off.

<StackEvidence stack="apps/seafile" />

**To try it:** Docker, nothing else. See [Try it locally](#try-it-locally).

**To deploy it behind the proxy:** [Traefik](/infrastructure/traefik/) running, a domain, and SMTP if the server should send invitations or reset links.

## Try it locally

On your own machine, with no proxy, domain or certificate. From `apps/seafile/`:

```bash
cp .env.local.example .env.local

# The secrets ship empty; generate the ones this stack needs
{
  echo "SEAFILE_DB_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "DB_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "REDIS_PASSWORD=$(openssl rand -hex 32)"
  echo "SEAFILE_ADMIN_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "JWT_PRIVATE_KEY=$(openssl rand -base64 48 | tr -d '\n')"
} >> .env.local

mkdir -p volumes/local/mysql volumes/local/redis volumes/local/seafile-data
sudo chown 999:999 volumes/local/mysql

docker compose -f docker-compose.local.yml --env-file .env.local up -d
```

Then open `http://127.0.0.1:8000`. Stop it again with the same command and `down`.

## What is in the stack

`COMPOSE_FILE` in `.env` decides which parts run. Removing a filename and running
`docker compose up -d` again switches that component off.

| File | Services | Required |
|---|---|---|
| `seafile-server.yml` | the server, MariaDB, memcached, Redis | yes |
| `seadoc.yml` | collaborative document editor | optional |
| `notification-server.yml` | push notifications for file changes | optional |
| `md-server.yml` | file metadata and extended properties | optional |
| `thumbnail-server.yml` | image and video thumbnails | optional |

All of them are served under one hostname; Traefik routes by path.

## Installation

From `apps/seafile/`:

<Steps>

1. Copy the environment file and set `APP_TRAEFIK_HOST`, `SEAFILE_ADMIN_EMAIL`
   and `TIMEZONE`:

   ```bash
   cp .env.example .env
   ```

2. Generate the secrets:

   ```bash
   mkdir -p .secrets
   openssl rand -base64 32 | tr -d '\n' > .secrets/db_root_pwd.txt
   openssl rand -base64 32 | tr -d '\n' > .secrets/seafile_db_pwd.txt
   openssl rand -base64 32 | tr -d '\n' > .secrets/seafile_admin_pwd.txt
   openssl rand -base64 48 | tr -d '\n' > .secrets/jwt_key.txt
   openssl rand -hex 32 | tr -d '\n' > .secrets/redis_pwd.txt
   ```

   The Redis password is hex, not base64: Seafile builds its Redis URL from it
   without escaping, and a `/` would end the URL early.

   The thumbnail server does not read Docker secrets; it takes two of these
   values from `.env`. Left empty, every thumbnail fails while the container
   reports healthy:

   ```bash
   sed -i "s|^JWT_PRIVATE_KEY=.*|JWT_PRIVATE_KEY=$(cat .secrets/jwt_key.txt)|" .env
   sed -i "s|^SEAFILE_MYSQL_DB_PASSWORD=.*|SEAFILE_MYSQL_DB_PASSWORD=$(cat .secrets/seafile_db_pwd.txt)|" .env
   ```

3. Create the SMTP secret file even if mail stays off — compose mounts it
   unconditionally:

   ```bash
   touch .secrets/smtp_pwd.txt                          # mail disabled
   # printf '%s' 'SMTP-PASSWORD' > .secrets/smtp_pwd.txt  # mail enabled
   ```

   The OnlyOffice secret file is mounted unconditionally as well. An empty file
   keeps the integration off; with OnlyOffice, reuse its secret:

   ```bash
   touch .secrets/onlyoffice_jwt_secret.txt                                       # no OnlyOffice
   # cp ../onlyoffice/.secrets/jwt_secret.txt .secrets/onlyoffice_jwt_secret.txt  # with OnlyOffice
   ```

4. Start it. The first boot initialises the databases and runs migrations, which
   takes two to four minutes:

   ```bash
   docker compose up -d
   docker compose logs seafile --follow
   ```

   Wait for `Seafile server started`.

5. Recreate the server container once. On the first boot Seafile writes
   `seahub_settings.py` after the entrypoint has already run, so the blueprint
   block — mail, document editing, metadata, thumbnails — is not in it yet:

   ```bash
   docker compose up -d --force-recreate seafile
   ```

6. Confirm the block arrived:

   ```bash
   docker compose exec seafile bash -lc \
     'grep -n "# --- Blueprint custom settings ---" /shared/seafile/conf/seahub_settings.py \
      || echo "STILL MISSING — check entrypoint logs"'
   ```

7. Open `https://<APP_TRAEFIK_HOST>` and log in as `SEAFILE_ADMIN_EMAIL` with the
   password from `.secrets/seafile_admin_pwd.txt`.

</Steps>

## Verify

```bash
docker compose ps   # eight services with the default COMPOSE_FILE
```

Then upload a file through the web interface and sync it with a desktop client.
Sync is what this stack exists for and it exercises paths the web interface does
not.

If mail is enabled, invite a user and confirm the message arrives. Without the
settings block from step 5, Seafile reports that the mail service is not
configured.

## Going further

### Private by default

The stack ships `access-trusted-vpn`, with `limit-sync` and `headers-standard`.
Seafile holds whatever people put in it, and the sync clients reach it over the
same hostname, so widening the access policy is a decision about every client at
once.

### Document editing

`seadoc.yml` adds the collaborative editor for `.sdoc` files. OnlyOffice is a
separate stack with its own hostname and is not routed through here — see
[OnlyOffice](/applications/onlyoffice/).

## Backup

| | |
|---|---|
| **Databases** | MariaDB, container `seafile-db`, **three databases**: `ccnet_db`, `seafile_db`, `seahub_db`, user `seafile` |
| **Password** | `.secrets/seafile_db_pwd.txt` |
| **State** | `volumes/mysql` · `volumes/seafile-data` (the file store) · `volumes/seadoc-data` |
| **Rebuildable** | `volumes/redis` · the log directory under `volumes/seafile-data` |
| **Quiescing** | Not needed. Seafile writes content-addressed blocks, so a file captured mid-write is a new block rather than a damaged one. |

For [borgmatic](/operations/backup/):

```yaml
mariadb_databases:
    - name: ccnet_db
      container: seafile-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile/.secrets/seafile_db_pwd.txt}"
    - name: seafile_db
      container: seafile-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile/.secrets/seafile_db_pwd.txt}"
    - name: seahub_db
      container: seafile-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile/.secrets/seafile_db_pwd.txt}"
```

All three are required: `seafile_db` holds the file metadata, `ccnet_db` the
users and groups, `seahub_db` the web layer with shares and links. Any one of them
missing produces a restore that starts and is unusable.

Restore order: the three databases, then the file store, then the application.

## Updates

<Steps>

1. Read the [release notes](https://manual.seafile.com/latest/changelog/server-changelog/).
   Seafile's major versions carry database migrations.

2. Back up all three databases and `volumes/seafile-data` together.

3. Raise the image variables in `.env`, then:

   ```bash
   docker compose pull && docker compose up -d
   docker compose logs seafile --follow
   ```

4. Log in and sync one file. A migration that touched the metadata tables shows
   up in the client rather than in the interface.

</Steps>

## Troubleshooting

**"Email service is not properly configured" right after installing.** The
settings block is missing. Run installation step 5, then check with step 6.

**Document editing, metadata or thumbnails are absent after a fresh install.**
Same cause, same fix.

**A restored instance starts but shares and links are gone.** Only some of the
three databases came back. All three are required.

**A component should be switched off.** Remove its filename from `COMPOSE_FILE`
in `.env` and run `docker compose up -d` again.
