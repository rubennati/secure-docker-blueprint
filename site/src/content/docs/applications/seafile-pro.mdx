Seafile Pro is private cloud storage with browser-based Office editing (OnlyOffice), collaborative document editing (SeaDoc), full-text search (SeaSearch) and antivirus scanning (ClamAV). Its services are split over Compose files that `COMPOSE_FILE` combines — the example enables seven — and it needs a commercial license. OnlyOffice is a separate server and is enabled only when `ONLYOFFICE_JWT_SECRET` is set; the example ships it empty.

<StackEvidence stack="apps/seafile-pro" />

**To try it:** Docker, and a Seafile Pro commercial licence, which the image requires either way. See [Try it locally](#try-it-locally).

**To deploy it behind the proxy:** [Traefik](/infrastructure/traefik/) running, a hostname, a Seafile Pro commercial license, and an external [OnlyOffice](/applications/onlyoffice/) instance for `.docx`/`.xlsx`/`.pptx` editing (optional — all other features work without it).

## Try it locally

On your own machine, with no proxy, domain or certificate. From `apps/seafile-pro/`:

```bash
cp .env.local.example .env.local

# The secrets ship empty; generate the ones this stack needs
{
  echo "SEAFILE_MYSQL_DB_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "INIT_SEAFILE_MYSQL_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "REDIS_PASSWORD=$(openssl rand -hex 32)"
  echo "INIT_SEAFILE_ADMIN_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')"
  echo "JWT_PRIVATE_KEY=$(openssl rand -base64 48 | tr -d '\n')"
} >> .env.local

mkdir -p volumes/local/mysql volumes/local/redis volumes/local/seafile-data
sudo chown 999:999 volumes/local/mysql

docker compose -f docker-compose.local.yml --env-file .env.local up -d
```

Then open `http://127.0.0.1:8001`. Stop it again with the same command and `down`.

## Installation

From `apps/seafile-pro/`:

<Steps>

1. ```bash
   cp .env.example .env
   ```

2. Set required values in `.env`:

   ```ini
   APP_TRAEFIK_HOST=files.example.com
   SEAFILE_ADMIN_EMAIL=admin@example.com
   TZ=Europe/Vienna
   ```

3. Generate passwords and the JWT key:

   ```bash
   sed -i "s|^INIT_SEAFILE_MYSQL_ROOT_PASSWORD=.*|INIT_SEAFILE_MYSQL_ROOT_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')|" .env
   sed -i "s|^SEAFILE_MYSQL_DB_PASSWORD=.*|SEAFILE_MYSQL_DB_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')|" .env
   sed -i "s|^INIT_SEAFILE_ADMIN_PASSWORD=.*|INIT_SEAFILE_ADMIN_PASSWORD=$(openssl rand -base64 32 | tr -d '\n')|" .env
   sed -i "s|^JWT_PRIVATE_KEY=.*|JWT_PRIVATE_KEY=$(openssl rand -base64 48 | tr -d '\n')|" .env
   sed -i "s|^REDIS_PASSWORD=.*|REDIS_PASSWORD=$(openssl rand -hex 32)|" .env
   ```

4. If using OnlyOffice, set the hostname and copy the JWT secret — it must match the OnlyOffice server exactly:

   ```ini
   ONLYOFFICE_HOST=office.example.com
   ```

   ```bash
   # sed -i "s|^ONLYOFFICE_JWT_SECRET=.*|ONLYOFFICE_JWT_SECRET=<value-from-apps/onlyoffice>|" .env
   ```

5. Pull images:

   ```bash
   docker compose pull
   ```

6. Start the stack:

   ```bash
   docker compose up -d
   ```

7. Wait for all containers to be healthy — first boot initialises the databases and takes roughly three minutes:

   ```bash
   docker compose ps
   ```

8. **Required:** restart the app container once to inject Blueprint configs into Seafile's settings files. This step only needs to run once — a marker prevents it from repeating on subsequent restarts:

   ```bash
   docker compose restart seafile-pro-app
   ```

9. Build the initial full-text search index:

   ```bash
   docker exec seafile-pro-app /opt/seafile/seafile-server-latest/pro/pro.py search --update
   ```

</Steps>

## Verify

```bash
docker compose ps   # every service of the files in COMPOSE_FILE up; app, db, redis, clamav should show healthy
```

Confirm the config injection from step 8 ran:

```bash
docker exec seafile-pro-app grep "Blueprint" /shared/seafile/conf/seahub_settings.py
docker exec seafile-pro-app grep "SEASEARCH"  /shared/seafile/conf/seafevents.conf
docker exec seafile-pro-app grep "virus_scan" /shared/seafile/conf/seafile.conf
```

Each command should return a matching line. No output means the injection step was skipped — run `docker compose restart seafile-pro-app` and recheck.

Confirm the notification server is reachable:

```bash
curl -s https://your-domain/notification/ping   # {"ret": "pong"}
```

Test antivirus:

```bash
docker exec seafile-pro-app bash -c "curl -s https://secure.eicar.org/eicar.com.txt | clamdscan -"
# Expected: stream: Eicar-Test-Signature FOUND
```

Then in the browser, confirm each service works:

- Log in with the admin account.
- Upload a file and download it back.
- Create and edit a Markdown (`.md`) file.
- Open a `.docx` in the OnlyOffice editor (requires OnlyOffice configured).
- Create a `.sdoc` file and open it in SeaDoc.
- Search for a word from an uploaded file — SeaSearch should return it.

## OnlyOffice

OnlyOffice embeds a browser-based Office editor into Seafile. It runs as a separate server — either another Blueprint stack or a different machine — and both sides share the same JWT secret.

**Server-to-server path:** OnlyOffice fetches the document from Seafile and saves it back through a callback. Seafile's route ships closed, and a closed route refuses every container, so on the same host these two paths have their own opt-in routes in `onlyoffice-callback.yml` (the same mechanism as [Seafile CE](/applications/seafile/#document-editing)); an OnlyOffice server on another host reaches a closed Seafile only by its address in `TRUSTED_RANGES`. DOCX, XLSX and PPTX open, save and reopen through `onlyoffice-callback.yml`.

**Allowed origins:** On the OnlyOffice server, add the Seafile origin to `ONLYOFFICE_ALLOWED_ORIGINS` in its `.env` so browsers are permitted to embed the editor in an iframe. In the Blueprint's `apps/onlyoffice` stack this value is embedded in a Traefik label — changing it takes effect only after recreating the container, not after a plain restart:

```bash
# On the OnlyOffice server:
docker compose up -d --force-recreate
```

## Going further

<Tabs>

  <TabItem label="SMTP">
    SMTP is optional but required for password reset emails, share invitations, and file change notifications. Set the SMTP variables in `.env`:

    ```ini
    SEAFILE_SMTP_HOST=smtp.example.com
    SEAFILE_SMTP_PORT=587
    SEAFILE_SMTP_USER=user@example.com
    SEAFILE_SMTP_FROM=seafile@example.com
    SEAFILE_SMTP_USE_TLS=true
    SEAFILE_SMTP_PASSWORD=your-smtp-password
    ```

    Then recreate the app so it picks up the new values — `docker compose
    restart` keeps the environment the container was created with, so a changed
    `.env` would have no effect:

    ```bash
    docker compose up -d seafile-pro-app
    ```

    Send a test email from the Seafile admin panel before relying on this for password resets. Mail delivery has not been exercised for this stack.
  </TabItem>

  <TabItem label="Access">
    The stack ships `APP_TRAEFIK_ACCESS=access-trusted-vpn` — the ranges declared in `core/traefik/.env` and the VPN; no closed policy admits a Docker container; SeaDoc calls Seafile over the internal network, and the two paths OnlyOffice uses — the document fetch and the save callback — have their own routes in `onlyoffice-callback.yml`. `access-public` removes Traefik's source-IP allowlist. Whether the service is actually reachable from the public internet depends on your DNS records, routing, and upstream firewall — the `access-public` middleware setting does not control any of that.

    Setting `APP_TRAEFIK_ACCESS=access-vpn` admits VPN clients only; the declared ranges no longer.

    With the shipped published ports Traefik sees a client's own address on IPv4 and IPv6 — measured from a client off the host; a tailnet client has not been measured yet. If it sees a Docker gateway address instead, see [Troubleshooting](#troubleshooting); widening the policy would admit every caller that arrives through that gateway.
  </TabItem>

  <TabItem label="Antivirus">
    ClamAV is included in the default `COMPOSE_FILE` and configured automatically when the Blueprint config injection runs (step 8 of the installation). Uploaded files are scanned on write.

    To verify ClamAV is active:

    ```bash
    docker exec seafile-pro-app bash -c "curl -s https://secure.eicar.org/eicar.com.txt | clamdscan -"
    # Expected: stream: Eicar-Test-Signature FOUND
    ```

    A startup log warning about the clamd socket (`Clamd was NOT notified`) is expected during container initialisation — it is a timing race and does not affect scanning once the container is up.
  </TabItem>

  <TabItem label="Search">
    SeaSearch is the default full-text search backend. It is lightweight and configured automatically by the config injection step — no manual setup required.

    Elasticsearch is available in the repository as a reference compose file (`elasticsearch.yml`) but is **not active** by default and not included in `COMPOSE_FILE`. Do not add it alongside SeaSearch — both cannot run simultaneously.

    Trigger a manual index rebuild after bulk uploads or a first install:

    ```bash
    docker exec seafile-pro-app /opt/seafile/seafile-server-latest/pro/pro.py search --update
    ```
  </TabItem>

</Tabs>

## Backup

[Backup and restore](/operations/backup/) covers the host side — Borgmatic, the
repository, the schedule and the database hooks. What this stack contributes:

- `volumes/seafile-data/` — all user files and library data
- `volumes/mysql/` — all three databases (Seafile, Seahub, Ccnet)
- `volumes/seadoc-data/` — collaborative document state
- The `.env` file and any secrets

The search index is not on that list. It is rebuilt rather than restored, with the
command under [Going further](#going-further).

The databases and the file volumes have to come back from the same point in time,
and all three databases together. A restore that recovers one side without the
other leaves the installation inconsistent rather than merely incomplete.

The database password lives in `.env`, and borgmatic reads credentials from a
file, so write one for it first:

```bash
mkdir -p .secrets
grep '^SEAFILE_MYSQL_DB_PASSWORD=' .env | cut -d= -f2- | tr -d '\n' > .secrets/seafile_db_pwd.txt
chmod 600 .secrets/seafile_db_pwd.txt
```

For [borgmatic](/operations/backup/):

```yaml
mariadb_databases:
    - name: ccnet_db
      container: seafile-pro-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile-pro/.secrets/seafile_db_pwd.txt}"
    - name: seafile_db
      container: seafile-pro-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile-pro/.secrets/seafile_db_pwd.txt}"
    - name: seahub_db
      container: seafile-pro-db
      username: seafile
      password: "{credential file /srv/docker/apps/seafile-pro/.secrets/seafile_db_pwd.txt}"
```

Restore order: databases, then the block store, then the application, then the
search reindex. A dump holds the databases, not the account Seafile connects with
— restored into a fresh `db` container, every request fails with `Access denied
for user 'seafile'`. Create the account before starting the app:

```bash
docker compose up -d db
# restore the three dumps, then:
docker compose exec -T db sh -c 'mariadb -uroot -p"$MYSQL_ROOT_PASSWORD"' <<SQL
CREATE USER IF NOT EXISTS 'seafile'@'%' IDENTIFIED BY '$(grep '^SEAFILE_MYSQL_DB_PASSWORD=' .env | cut -d= -f2- | tr -d '\n')';
GRANT ALL PRIVILEGES ON ccnet_db.* TO 'seafile'@'%';
GRANT ALL PRIVILEGES ON seafile_db.* TO 'seafile'@'%';
GRANT ALL PRIVILEGES ON seahub_db.* TO 'seafile'@'%';
SQL
docker compose up -d
```

## Updates

This sequence follows the upstream Docker upgrade guide.

<Steps>

1. Read the [Seafile Pro release notes](https://manual.seafile.com/changelog/server-changelog/) and the [Docker upgrade guide](https://manual.seafile.com/upgrade/upgrade_docker/) for breaking changes.
2. Back up all volumes before touching the stack.
3. Update image tags in `.env` — `APP_TAG` for the main server, and the tags for any component services that changed.
4. Pull and recreate:

   ```bash
   docker compose pull
   docker compose up -d
   ```

5. Watch app logs for any database migration output:

   ```bash
   docker compose logs -f seafile-pro-app
   ```

6. Verify login, file access, editing, and search after the update.

</Steps>

## Troubleshooting

**OnlyOffice editor not loading:** either a JWT mismatch — `ONLYOFFICE_JWT_SECRET` in `apps/seafile-pro/.env` has to match the secret on the OnlyOffice server exactly — or the Seafile origin is missing from `ONLYOFFICE_ALLOWED_ORIGINS` on the OnlyOffice side.

**Allowed-origins change has no effect:** `ONLYOFFICE_ALLOWED_ORIGINS` is embedded in a Traefik label at container creation time, so a plain `docker compose restart` does not pick up a new value. Run `docker compose up -d --force-recreate` on the OnlyOffice server.

**ClamAV socket warning in startup logs:** the line `Clamd was NOT notified: Can't connect to clamd through /tmp/clamd.sock` is a timing race during container initialisation and is non-fatal. Run the EICAR test in Verify to confirm scanning is active.

**MariaDB `io_uring` warning or Redis memory overcommit warning:** both are host-level configuration notices, not application errors. To silence the Redis warning, set `vm.overcommit_memory = 1` in `/etc/sysctl.conf` on the host and apply it with `sysctl -p`. The MariaDB notice needs no action — it falls back to libaio on its own.

**`access-vpn` returning 403 for a Tailscale client:** see [Traefik troubleshooting](/infrastructure/traefik/#troubleshooting) for the source-IP caveat when traffic arrives through Docker published ports.
