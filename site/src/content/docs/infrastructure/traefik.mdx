Traefik is the reverse proxy every other service sits behind — it terminates TLS and routes requests to the right container. Set it up first.

## Installation

This path uses Cloudflare DNS-01 for a wildcard certificate — it doesn't require port 80 to be publicly reachable. Needs: a domain with DNS at Cloudflare, and a Cloudflare API token (My Profile → API Tokens → Custom Token, with `Zone:DNS:Edit` + `Zone:Zone:Read`).

Don't use Cloudflare, or don't want a wildcard? See "Certificate strategy" under [Going further](#going-further) — per-domain certificates work with or without Cloudflare.

<Steps>

1. From `core/traefik/`:

   ```bash
   cp .env.example .env
   ```

2. Set these in `.env`:

   ```ini
   ACME_EMAIL=you@example.com
   TRAEFIK_DASHBOARD_HOST=traefik.example.com
   CF_DNS_API_TOKEN=<your Cloudflare token>
   ACME_WILDCARD_DOMAIN=example.com
   ```

3. Render and start:

   ```bash
   bash ops/scripts/render.sh
   docker compose up -d
   ```

4. Confirm both containers are healthy:

   ```bash
   docker compose ps
   ```

</Steps>

## Verify

```bash
curl -I https://<your-dashboard-domain>
```

The dashboard is Tailscale-only by default — connect over your tailnet to reach it.

:::note
`docker compose logs traefik` shows nothing — this is expected. Traefik writes logs to files, not stdout:

```bash
docker exec traefik-core cat /var/log/traefik/traefik.log     # startup, ACME, errors
docker exec traefik-core cat /var/log/traefik/access.log      # every HTTP request
```
:::

Check certificate issuance:

```bash
docker exec traefik-core cat /etc/traefik/acme/acme.json | jq '.[] | .Certificates[]?.domain // "no certs yet"'
```

## Going further

### Networking: dual-stack by default, two bind variables

Host ingress is two variables in `core/traefik/.env`, one per address family:
`TRAEFIK_BIND_V4` and `TRAEFIK_BIND_V6`. `render.sh` writes them into
`config/published-ports.yml`, which `COMPOSE_FILE` applies; `docker-compose.yml`
publishes nothing itself. An empty variable publishes nothing for its family, and
neither has a default — `render.sh` refuses `TRAEFIK_BIND_V4` unset, so a missing
line never binds every address. An IPv6 binding needs `network-dual-stack.yml`,
which makes the proxy network carry IPv6; `render.sh` refuses one without it.

The failure dual-stack prevents, in this architecture, is **Tailscale**: it always
hands a client both addresses, and if the client connects over IPv6 to a proxy
network without IPv6, Docker hands the connection to Traefik from the bridge
gateway — the access policy then sees a private address, not the client, and
answers 403. Traffic arriving through a Cloudflare-proxied (orange-cloud) record is
unaffected, because the real address is recovered from a trusted forwarded header.

<Tabs>
  <TabItem label="Dual-stack (default)">
    <Steps>

    1. Generate your own IPv6 ULA prefix — the example in `.env.example` is refused on purpose:

       ```bash
       RANDOM_HEX=$(openssl rand -hex 5)
       printf 'fd%s:%s:%s::/64\n' "${RANDOM_HEX:0:2}" "${RANDOM_HEX:2:4}" "${RANDOM_HEX:6:4}"
       ```

    2. Check for subnet conflicts:

       ```bash
       docker network ls
       docker network inspect <network-name> --format '{{range .IPAM.Config}}{{.Subnet}} {{end}}'
       ```

    3. Back up and edit `/etc/docker/daemon.json`, merging in:

       ```json
       {
         "ipv6": true,
         "ip6tables": true,
         "userland-proxy": false
       }
       ```

       Then restart the daemon — this briefly affects every container on the host:

       ```bash
       sudo systemctl restart docker
       ```

    4. In `core/traefik/.env`, set the prefix; the rest is the example's default:

       ```ini
       PUBLIC_NETWORK_SUBNET_V4=172.30.0.0/16
       PUBLIC_NETWORK_SUBNET_V6=<your generated prefix>/64
       TRAEFIK_BIND_V4=0.0.0.0
       TRAEFIK_BIND_V6=[::]
       COMPOSE_FILE=docker-compose.yml:network-dual-stack.yml:config/published-ports.yml:config/edge-networks.yml
       ```

    </Steps>
  </TabItem>
  <TabItem label="IPv4 only">
    Leave `TRAEFIK_BIND_V6` empty and drop the overlay from the list:

    ```ini
    TRAEFIK_BIND_V6=
    COMPOSE_FILE=docker-compose.yml:config/published-ports.yml:config/edge-networks.yml
    ```

    A Tailscale client is then served over IPv4 only.
  </TabItem>
  <TabItem label="IPv6 only">
    Leave `TRAEFIK_BIND_V4` empty and keep the overlay: no public IPv4 ingress. What
    the host needs for IPv6-only outbound connections — registries and sources without
    `AAAA` records — is a prerequisite list, not a mode; see the ingress audit, §3.4.
    Not verified on a host yet.
  </TabItem>
</Tabs>

:::caution
`COMPOSE_FILE` lives in `.env`, never on the command line. A command run without the
network overlay would recreate `proxy-public` as IPv4-only, and one run without the
rendered file would publish nothing. Run `bash ops/scripts/render.sh` after changing a
binding. Adding dual-stack to an already-running IPv4-only deployment is a parallel
network and a cutover, not an overlay applied to the live network:
[`core/traefik/docs/ipv6-dual-stack.md`](https://github.com/rubennati/secure-docker-blueprint/blob/main/core/traefik/docs/ipv6-dual-stack.md).
:::

### Certificate strategy

The path above is one of four. The others work too — the only hard constraint is that wildcard certificates require DNS-01, since Let's Encrypt issues wildcards over no other challenge, whatever the server can reach.

<Tabs>
  <TabItem label="Wildcard">
    One DNS-01 certificate covers `*.example.com` — what the installation above sets up. Needs a Cloudflare account and token; does **not** need port 80 reachable from the internet. Best when several services share one domain, and keeps covered service names out of public Certificate Transparency logs — including the Traefik dashboard, which uses the same certificate. Leave `TRAEFIK_DASHBOARD_CERT_RESOLVER` empty for that. A wildcard matches exactly one label: `traefik.example.com` is covered, `traefik.admin.example.com` is not.
  </TabItem>
  <TabItem label="Per-domain (DNS-01)">
    Each application requests its own DNS-01 certificate through Cloudflare — still no public port 80 needed. Leave `ACME_WILDCARD_DOMAIN` unset; in each app's `.env` set `APP_TRAEFIK_CERT_RESOLVER=cloudflare-dns`, and uncomment the `tls.certresolver` label in its `docker-compose.yml`.
  </TabItem>
  <TabItem label="Per-domain (HTTP-01)">
    Each application requests its own certificate via the standard HTTP-01 challenge — no Cloudflare account or token at all. Requires port 80 to be publicly reachable on this server. Leave `ACME_WILDCARD_DOMAIN` unset; in each app's `.env` set `APP_TRAEFIK_CERT_RESOLVER=httpResolver`, and uncomment the `tls.certresolver` label. On both per-domain paths the dashboard needs `TRAEFIK_DASHBOARD_CERT_RESOLVER` set as well.
  </TabItem>
  <TabItem label="Per-domain (TLS-ALPN-01)">
    Each application requests its own certificate over **port 443 itself** — Let's Encrypt opens a TLS connection, asks for the ALPN protocol `acme-tls/1`, and Traefik answers on the port it already listens on. No port 80 forward, no Cloudflare account, no DNS credentials: a firewall that forwards a single TCP port is enough. Leave `ACME_WILDCARD_DOMAIN` unset; in each app's `.env` set `APP_TRAEFIK_CERT_RESOLVER=tlsResolver`, and uncomment the `tls.certresolver` label.

    Two things rule it out: a wildcard (DNS-01 only), and anything that terminates TLS in front of this server. A CDN or load balancer answers the handshake itself and never forwards the ALPN protocol, so issuance fails with `cannot negotiate ALPN protocol "acme-tls/1"` — **including Cloudflare's proxy on orange cloud.** Set the record to DNS-only, or use a DNS-01 resolver there.
  </TabItem>
</Tabs>

These combine, too: keep a wildcard for your main domain and let individual apps opt into their own certificate (either resolver) via the same per-app label.

The setup check refuses the one combination that fails silently — no wildcard covering a hostname and no resolver for it — because Traefik answers such a request with its own self-signed certificate and writes nothing to the log. When upgrading a wildcard installation that already issued a separate dashboard certificate, emptying the variable stops further requests for it; the certificate already stored keeps renewing, and a hostname already in the transparency logs stays there.

Cloudflare's proxy status (orange-cloud vs. DNS-only) is a separate, per-record choice, and it is irrelevant to every path above except one: TLS-ALPN-01 needs the TLS handshake to reach this server, so an orange-cloud record breaks it and a DNS-only record does not.

## Troubleshooting

:::caution
**A 403 from a Tailscale client that should be allowed** — check the access log's `ClientHost` field. `100.x.x.x` or `fd7a:115c:a1e0::...` is correct. `172.x.x.x` from a remote client is the dual-stack issue above. `172.x.x.x` from a `curl` run *on the Traefik host itself* is a different, harmless Docker behavior (hairpin NAT) — test from a separate client instead.
:::

```bash
docker compose logs traefik 2>&1 | grep -iE "acme|cert|challenge" | tail -20
```

Most first-setup certificate failures are a Cloudflare token missing zone permissions, or a mismatch between `ACME_WILDCARD_DOMAIN` and the per-app `tls.certresolver` label state.

:::tip
`docker compose config` prints every `.env` value, including `CF_DNS_API_TOKEN`. Redact before sharing it anywhere:

```bash
docker compose config | sed -E 's/(CF_DNS_API_TOKEN: ).*/\1***REDACTED***/'
```
:::

## Updates

```bash
# Read release notes first: https://github.com/traefik/traefik/releases
# Bump TRAEFIK_IMAGE in .env, then:
bash ops/scripts/render.sh
docker compose pull
docker compose up -d
docker compose logs traefik 2>&1 | grep -i error   # should be empty
```

Never jump major versions without reading the migration guide — the configuration schema changes.
