## Deviations from the plan

- **X1 in two runs, one per address.** The first external run used the script
  before `8f19db3` and measured nothing valid. With `8f19db3` the operator ran it
  from OUT once against H1's IPv4 address and once against its IPv6 address;
  both held the `direct` profile. A run from the host against itself was not
  counted. `validate.sh` reads the last marker line of
  `config/exposure-verified`, so both lines are kept in the file, IPv4 first.
- **A9.** The plan expects 403 over `[::1]`. With `userland-proxy: false` Docker
  does not forward the IPv6 loopback address to a container, which
  `core/traefik/docs/ipv6-dual-stack.md` states; the connection times out. The
  gate is not bypassed — over the host's global IPv6 address and over
  `127.0.0.1` the answer is 403. The expected value of A9 contradicts the
  documentation.
- **N and G4 without a VPN.** Every policy but `access-public` refuses the
  host's own requests, and 403 from the access middleware proves nothing about
  the backend. The probes therefore used test-only routers with
  `Host(…) && ClientIP(<gateway of proxy-public>)` and `access-public`: only the
  host itself matches, every other client gets 404. G4 ran on Heimdall's own
  router with that rule and `access-public` for its duration, so the basicAuth
  gate is what answered.
- **N2, step 4 of the first move** was skipped by the lab's helper script (it
  stopped on the expected exit 1 of `--strict` while the marker is open); N4
  ran it afterwards.
- **Rows not run in this phase:** the TS and LAN columns of A, A8, F1–F9, M2,
  G1, G3, G5–G7, S2, X4 and O. F stays open by decision: the rendered ruleset
  admits management from the VPN ranges only, and without a VPN loading it
  would close SSH over the public address.

## Findings

1. **A Traefik recreate interrupts every stack for about seven seconds** (N2,
   N5). Measured with a probe every 0.2 s against three stacks: from the stop
   signal Traefik accepts no new connection; the old container needs 3.3–4.8 s
   to exit and the new one 1.6–2.0 s to start, 6.5–7.3 s in all. The "about two
   seconds" of the 2026-10-31 lab run (DEC-075, `edge-networks.md`) covers the
   start alone, and "the other stacks stay served" in step 1 of "Moving a shared
   installation" does not hold: they are interrupted for the recreate. `edge-networks.md`
   and `.env.example` now state the measured figures. The moved
   stack is unreachable in addition until its healthcheck passes (Traefik skips
   a starting container): about 5 s for httpbin and it-tools, under 1 s for
   whoami, which has none.
2. **Moving back, list first, cuts the stack off between step 1 and step 3**
   (N5): "Moving back is the same steps with the old value" shortens
   `EDGE_NETWORKS` and recreates Traefik before the stack leaves its edge
   network. Moving the stack to `proxy-public` first and shortening the list
   afterwards keeps the interruptions apart and short — measured for whoami: its
   own recreate 2.3 s, then Traefik's 4.5 s, against one stretch of about 14 s
   list first for a stack with a healthcheck. `edge-networks.md` now describes
   the way back in that order.
3. **A removed edge network stays on the host.** Traefik's Compose project no
   longer names it, and nothing removes it; on a default daemon it keeps using
   one of the 32 address pools until `docker network rm`.
4. **v0.9.5 in the IPv4-only shape maps the published ports to
   `crowdsec-security`** (B1): the measurement behind step 2, on a host. In the
   dual-stack shape v0.9.5 already landed on `proxy-public`, the only network
   with both families.
5. **Automated scans began within two minutes of the first certificate.**
   Requests to the test zone's base name, which no router serves: one source
   sent about 1 270 requests in 16 seconds (`.env`, `.git/config`, WordPress
   paths), all answered 404, as were the others. No request from outside reached
   a closed router. A request no router matches meets no rate limit — the limits
   are positions of a router — and CrowdSec was not installed; `validate.sh`
   names that layer as absent with its residual risk. The access log records no
   request headers, so a browser and a scanner cannot be told apart in it.
6. **DNS-01 under a wildcard CNAME.** The test zone carries `*.<zone>` as a
   CNAME to the base name, so `_acme-challenge.<zone>` resolves through it and
   the ACME client set its TXT record on the base name. Issuance worked and the
   record was removed afterwards; a property of the test zone, not of the
   blueprint.
7. **Traefik 3.7.17 warns at start that `aliasHeadersStrategy` is unset**, once
   per entrypoint — recorded as expected in `core/traefik/UPSTREAM.md`.
8. **The CI tests read the host they run on.** The fixtures named the
   deployment's container, `traefik-core`, and `validate.sh` inspects the
   running container of that name: on the lab host the suite measured the lab's
   Traefik. With the N4 correction ten tests failed there for that reason alone;
   the fixtures now use a name no deployment uses. A runner without a Traefik
   container was never affected.
