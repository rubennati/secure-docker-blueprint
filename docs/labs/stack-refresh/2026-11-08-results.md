# Stack refresh — lab results, 2026-11-08

What a run on two lab machines established for the stacks of this repository: which
pins moved and why the rest stayed, which stacks passed the five checks of
[`docs/host-session-priority-1.md`](../../host-session-priority-1.md), what was
corrected, what was measured and implemented (capabilities, memory limits, FA-03), and
the resource peaks. The local test stacks are reported in
`docs/labs/stack-refresh/2026-11-08-local-stacks.md`, on the branch
`lab/stack-refresh-2026-11-08-ct`.

The machines are named by role: **the lab host (VM)**, where every host run took place,
and **the lab container (LXC)**, which ran the local test stacks and the agents of the
management tools, and served as a client of check 3.

## Summary

- **119 of 121 stacks passed the five checks on the lab host** and carry a `Last verified`
  line from this run. `core/traefik` passed as well and keeps its line of 2026-11-01, which
  covered dual-stack and outside access; `apps/vllm` was not run (no GPU).
- **31 stacks moved to a newer pin**, among them two majors (`apps/docker-mailserver` 17,
  `monitoring/zabbix` 8.0 LTS) and the MinIO replacement Silo in two stacks. Where a pin
  stayed behind the newest upstream tag, the table names the reason: a pre-release (n8n),
  an unreleased line (Seafile 14), a channel the checker cannot compare.
- **53 corrections**: closed-by-default routes for first-visitor takeovers, start failures
  of root-without-capabilities containers, missing secrets and setup steps, a withdrawn image,
  an open conversion service, three watchdog faults, a placeholder that opened an admin panel.
- **Implemented from measurements**: capabilities for nine services, raised memory limits for
  twenty-one, FA-03's `docker exec` dump client in 25 READMEs, Silo, the Collabora closure.
- **Thirteen restore rehearsals**, all with row counts identical per table.

## Collabora behind Nextcloud's closed route

As asked, `/cool/convert-to` is closed on Collabora's public route: a second router of
higher priority answers it with `access-blocked`. The path converts any uploaded file

## UrBackup

The server started for the first time on a host and failed at once: the entrypoint writes
into `/var/urbackup` as root and checks both directories as uid 101 through `su`; with
`cap_drop: ALL` and operator-owned directories it restarted forever. Measured fix: both
directories root-owned and group-writable for gid 101, and `SETUID`, `SETGID` added (without
them `su` fails with "cannot set groups"). The image has neither `curl` nor `wget`, so the
shipped healthcheck could never pass and Traefik would have dropped the container; it now
uses bash's `/dev/tcp`. The administrator is created with `urbackupsrv reset-admin-pw`
before the host name is reachable; an anonymous login is then refused.

The lab container ran the Linux client 2.5.31 (2.5.32 ships no Linux installer), added by
address. A full file backup of four files completed, and the four files downloaded from
the server matched their checksums — also after `down`/`up`. A restore to the client itself
stopped at the client's own permission check ("No permissions to create files"); that is
the client in an unprivileged LXC and was not repeated elsewhere.

## Host watchdogs

Both scripts were installed from the host-files manifest and rehearsed with Healthchecks as
the receiver:

| Rehearsal | Docker daemon watchdog | Traefik watchdog |
|---|---|---|
| Fault | `dockerd` frozen (`SIGSTOP`): process alive, API hanging | Traefik frozen; `unhealthy` after 40 s |
| Confirmation | "streak 1/3", "2/3", restart on the third run | restart on the third unhealthy check |
| Result | "daemon now responding"; all ten containers running 58 s after the first run | "restarted after 3 unhealthy checks, now healthy" |
| Escalation (restarted service frozen again at once) | after the fixes: escalated after 35 s, the next run reported failure without another restart | after the fix: one restart, `escalated`, no further restart; healthy again after the process resumed |

The rehearsal found three faults, fixed:

- The Traefik watchdog took `starting` after its restart for success. A restart that did
  not help reset the episode, and the next confirmation restarted Traefik again — the
  endless retry the README rules out. Only `healthy` counts now (`START_TIMEOUT`).
- The Docker watchdog waited without limit in `systemctl restart docker` for a daemon that
  hung while starting (`docker.service` has no start timeout) and sent no ping.
  `RESTART_TIMEOUT` bounds it.
- Its unit was ordered after `docker.service`, so every later run queued behind the hanging
  start job. The ordering is gone.

In one of three double faults Traefik alone stayed `Exited (137)` after the daemon came back
and needed `up -d`; the watchdog checks the daemon, not the containers (recorded in its
README). A Healthchecks on the same host behind a closed policy cannot receive the pings:
a request from the Docker host reaches Traefik as `proxy-public`'s gateway, which
`validate.sh` rightly refuses in `TRUSTED_RANGES` — for the lab run Healthchecks was opened
in the lab's `.env` only; see the suggestions.

### Incidents

- **The hypervisor crashed** on 2026-11-08 under memory overcommit — the VM's 16 GiB without a
  balloon plus the other guests came to about 57 GB committed on a 31 GiB host. It was rebooted
  by its owner; every guest was then set not to start at boot, four unrelated VMs stayed stopped,
  and the VM and the container were sized up only within the host's memory.
- **containerd stalled** on 2026-11-09 with fourteen stacks pulling and unpacking at once while
  the lab container ran its own stacks on the same SSDs: direct writes at 11 MB/s, I/O pressure
  above 50 %, `failed to cleanup extract … DeadlineExceeded`, and even `docker run alpine`
  hung. Restarting containerd and Docker, pruning images and starting in groups of four cleared
  it. After that restart `dockhand-db` (exit 0) and `portainer-app` (exit 2) stayed down despite
  `unless-stopped`, as Traefik once did in the watchdog rehearsal — the daemon-restart path, not
  the reboot path, which brought everything back.
- **The VM ran out of memory** shortly after, with about twenty large stacks up at once: SSH
  stopped answering, and the VM was reset. Afterwards the large stacks ran two to four at a time.
  On this storage, parallel starts are bound by I/O first and memory second.

## From zero to a running host

What the path from an empty Debian 13 machine to Traefik, CrowdSec and the first
stack was, in order:

1. Docker from Docker's repository and the daemon settings — `docs/host-baseline.md`
   lists them as a table of what the earlier host had, not as steps; the order
   (address pools before the first network) is only in SHOULD 5.
2. `core/traefik`: `cp .env.example .env`, then the choices of the setup table.
   For an IPv4-only host the README said to drop the overlay and empty
   `TRAEFIK_BIND_V6`; `validate.sh` still refused the shipped example
   `PUBLIC_NETWORK_SUBNET_V6` — corrected in the README and `.env.example`.
3. `ACME_EMAIL` is required by `validate.sh`; Let's Encrypt no longer needs an
   address, and an `example.com` address is refused by Let's Encrypt, so an
   operator needs a real or at least a resolvable domain here.
4. There is no switch for Let's Encrypt staging; the staging run needed a hand
   edit of the rendered `config/traefik.yml` (`caServer`), which the next
   `render.sh` removes.
5. The Cloudflare token worked with `Zone → DNS → Edit` alone, scoped to the one
   zone; `Zone → Zone → Read` was not needed for the zone lookup.
6. `core/crowdsec`: setup as written; step 5 (`ops/allowlist.sh apply`) failed until
   the fix above.
7. The bouncer: key, `.env`, `render.sh`, `--force-recreate` — as written.
8. The first stack (`apps/whoami`) needed `APP_TRAEFIK_ACCESS=access-trusted`: the
   shipped `access-vpn` refuses every client on a host without a VPN.

## Suggestions for coordination

Nothing here is implemented; each needs a decision or belongs to the coordination.

1. **UniFi and CrowdSec cannot run on one host as shipped.** `apps/unifi` publishes `8080`
   (the devices' inform port) on `0.0.0.0`, `core/crowdsec` publishes `127.0.0.1:8080` for the
   host firewall bouncer; UniFi fails with `Bind for 127.0.0.1:8080 … already allocated`.
   Either CrowdSec's local API port moves (touches the firewall-bouncer docs) or UniFi's inform
   port does (devices need `set-inform`). **A decision.**
2. **Pinging a Healthchecks on the same host behind a closed policy.** A host job (the
   watchdogs, borgmatic) reaches Traefik as `proxy-public`'s gateway, which `validate.sh`
   rightly refuses in `TRUSTED_RANGES`. Options: a `/ping/` router on `monitoring/healthchecks`
   that admits the host (ping UUIDs are the secret, as Healthchecks intends), or a Healthchecks
   on another host. **A decision.**
3. **A placeholder left in `.env` can be a working credential.** Measured for Vaultwarden's
   admin panel (corrected). The same shape, not tested: `ADMIN_PASSWORD=__REPLACE_ME__` in
   `apps/librephotos`, `apps/photoprism`, `business/kimai`, `INIT_SEAFILE_ADMIN_PASSWORD` in
   `apps/seafile-pro` — 26 secret-like placeholders in all. A check, in CI or as an
   entrypoint guard, that refuses the literal placeholder at start would close the class.
4. **`DAC_READ_SEARCH` in the capability baseline.** It is narrower than `DAC_OVERRIDE`
   (read and search only) and the one MongoDB needs with a bind mount; today it needs an
   exception entry while the broader capability does not.
5. **A checker for first-visitor takeover.** Six stacks shipped `access-public` while the first
   visitor became the administrator (OpnForm, Immich, Lychee, Zammad, authentik, BookStack —
   corrected). `check-baseline.py` could require a closed policy, or a reasoned exception, for a
   stack whose README names a first-run setup page.
6. **Root without capabilities and an operator-owned mount.** NocoDB, Velociraptor, ShellHub,
   Orion-Belt, Teleport and UrBackup could not write (or read) what the README's `mkdir` or
   secrets created. `check-baseline.py` could flag `cap_drop: ALL` without `user:` on a service
   with a writable bind mount or a mode-600 secret.
7. **The local headers and the README.** Twenty local files lacked the README's `chown`
   (corrected); a check comparing the two would keep them aligned.
8. **A check that every `@file` reference exists** in Traefik's dynamic configuration —
   `apps/unifi` named an undefined servers transport, Warpgate none, and Traefik dropped the
   router.
9. **A check that a digest pin is the digest of its tag.** `business/vikunja` built 2.3.0 while
   naming 2.6.0 (corrected); `business/akaunting`'s `3.3.0-v` was re-pushed upstream since its pin.
10. **Docker daemon restarts.** After `systemctl restart docker` some `unless-stopped` containers
    stayed down (Traefik, a Dockhand database, Portainer) — a reboot brought everything back.
    The Docker watchdog checks the daemon only; whether it should also check that the
    containers came back is a design question.
11. **Port and name clashes worth a line in the READMEs:** `core/jumpserver` and
    `core/orion-belt` both publish `2222`; `monitoring/beszel` and `monitoring/beszel-agent`
    both name a container `beszel-agent` (by design for different hosts).
12. **OpnForm's nginx resolves its upstreams once.** Recreating only `opnform-ui` left `/` at
    `502` until nginx restarted; a resolver with a variable upstream would avoid it.
13. **Carried over:** the render-identity unit test fails in a live checkout (it copies the
    untracked rendered `config/`); a Let's Encrypt staging switch for `core/traefik`; borgmatic
    reports a failed `pg_restore` as a UTF-8 decode error; one-off commands in containers whose
    entrypoint reads secrets (Paperless, OpenProject) need a documented way.
